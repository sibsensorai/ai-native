# Управление скиллами по отделам

Схема владения скиллами компании «Сибсенсор»: главный владелец наверху,
под ним — владельцы скиллов по отделам, в основании — сотрудники.

## Роли

- **Главный владелец** (Алексей Лукин + Иван Шелемба) — отвечает за весь общий
  набор скиллов, утверждает что угодно, контролирует все отделы.
- **Владелец скиллов отдела** (продажи, производство, IT, …) — отвечает за скиллы
  своего направления: собирает черновики сотрудников, оформляет заявку, утверждает
  по своему отделу.
- **Сотрудник** — предлагает черновик скилла владельцу своего отдела.

## Как отдел отражается в репозитории

- **Отдел = набор (pack)** в `agent-platform/skill-packs.json`:
  `sibsensor-sales`, `sibsensor-production`, `sibsensor-it`, …
- **Принадлежность отделу — префикс в имени скилла** (папки в `skills/` плоские):
  - продажи → `skills/sales-<имя>/`
  - производство → `skills/prod-<имя>/`
  - IT → `skills/it-<имя>/`
- По этим префиксам `.github/CODEOWNERS` назначает владельца отдела.

## Кто что утверждает (CODEOWNERS)

Заявку по скиллам отдела может одобрить **владелец этого отдела ИЛИ главный владелец**:

```
/skills/sales-*/   @главный  @владелец-продаж
/skills/prod-*/    @главный  @владелец-производства
/skills/it-*/      @главный  @владелец-it
/skills/           @главный            # главный владелец — на всё
```

## Поток добавления скилла

**Сотрудник к GitHub не прикасается — всё идёт через ядро.**

1. Сотрудник решает задачу с ИИ → просит «упакуй в скилл». Агент отдела
   (`it-owner` и т.п.) готовит черновик.
2. **Агент подаёт заявку ЧЕРЕЗ ЯДРО** — `gateway_approval_create`
   (`approval_type: skill_proposal`, в payload — черновик `SKILL.md`/`skill.yaml`)
   и `gateway_notification_publish` владельцам. Никаких PR и пушей от сотрудника.
3. **Владелец** (Лукин / Шелемба) видит заявку и черновик в ядре (уведомления,
   `gateway_approval_list`), решает: одобрить (`gateway_approval_decide`) или отклонить.
4. После одобрения **куратор** (у кого есть доступ к репозиторию) публикует навык:
   кладёт `skills/<отдел>-<имя>/`, добавляет в pack, открывает PR →
   **автопроверка (CI)** → merge в `main`.
5. Магазин раздаёт новый навык всей команде.

> GitHub используется только на шаге 4 (публикация куратором). Шаги 1–3 — целиком в ядре.

## Как добавить новый отдел

1. Завести pack в `skill-packs.json` (`sibsensor-<отдел>`), выбрать префикс имён.
2. Добавить строку в `.github/CODEOWNERS` с владельцем отдела.
3. Дать владельцу отдела доступ на запись в репозиторий.
