# Контроль скиллов: что попадёт в общий набор

Общий набор скиллов компании раздаётся всем сотрудникам из ветки `main`.
Чтобы туда ничего не попадало «мимо вас», действует два рубежа:

1. **Автопроверка (CI).** На каждую заявку на изменение (Pull Request) GitHub
   сам запускает проверки: тесты, `validate-skills`, сборку и сверку плагинов.
   Не прошло — влить нельзя.
2. **Одобрение владельцев.** Влить в `main` можно только после одобрения
   кого-то из владельцев — **Алексей Лукин** или **Иван Шелемба**
   (заданы в `.github/CODEOWNERS`).

Итог: новый или изменённый скилл попадёт в общий набор, только если
**прошёл автопроверку И одобрен вами**.

## Как это выглядит на практике

- **Сотрудник** (без техники): решает задачу с ИИ → просит «упакуй в скилл» →
  присылает черновик куратору (ИТ). Сам в репозиторий не лезет.
- **Куратор/вы**: кладёт скилл в ветку, открывает Pull Request → ждёт зелёной
  автопроверки → второй владелец (или вы) одобряет → вливает в `main`.
- Прямой пуш в `main` закрыт защитой ветки (см. ниже) — всё только через PR.

## Как включить защиту ветки `main` (делает владелец, один раз)

GitHub → репозиторий `sibsensorai/ai-native` → **Settings** → **Branches** →
**Add branch ruleset** (или «Add rule») для ветки `main` и включить:

- ✅ **Require a pull request before merging** → **Require approvals: 1**
- ✅ **Require review from Code Owners**
- ✅ **Require status checks to pass** → выбрать проверку **CI / validate**
- ✅ **Do not allow bypassing the above settings** (чтобы правило касалось и админов)

После этого в `main` нельзя влить ничего без зелёной проверки и вашего одобрения.

## Кто может одобрять
Только владельцы из `.github/CODEOWNERS` (сейчас — Алексей; Иван добавляется,
когда известен его GitHub-логин). Остальные могут предлагать (PR), но не утверждать.
